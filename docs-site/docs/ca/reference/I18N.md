# ChillGroup v2 — Internacionalització (i18n)

## Filosofia

- **Tot text de UI passa per `t()`**: cap string visible hardcoded als components.
- **Català és l'idioma base i el fallback**: si falta una clau en un altre idioma, es mostra el català.
- **Catàlegs plans per idioma**: un únic fitxer `translation.json` per idioma, amb namespaces de primer nivell.
- **Errors del backend en català + codi**: el backend envia el missatge en català; el frontend el tradueix pel codi numèric (veure [ERRORS.md](ERRORS.md)).
- **Determinisme als tests**: l'idioma es força a `ca` perquè les asercions de text no depenguin del navegador.

## Stack

| Llibreria | Versió | Què fa |
|-----------|--------|--------|
| `i18next` | ^26 | Motor i18n (catàlegs, interpolació, fallback) |
| `react-i18next` | ^17 | Binding React: hook `useTranslation`, re-render en canviar idioma |
| `i18next-browser-languagedetector` | ^8 | Detecta idioma per `localStorage` → navegador |

Instal·lació (es fa servir **pnpm**):

```bash
pnpm add i18next react-i18next i18next-browser-languagedetector
```

## Estructura de fitxers

```
frontend/src/i18n/
  index.ts                 # init i18next, SUPPORTED_LNGS, config detector
  apiError.ts              # translateApiError(): codi backend → traducció
  apiError.test.ts         # tests del mapeig d'errors
  locales/
    ca/translation.json    # catàleg català (BASE — sempre complet)
    en/translation.json    # catàleg anglès
```

- `src/i18n/index.ts` s'importa a `src/main.tsx` **abans** de `<App/>` perquè la init sigui síncrona.
- `src/test-setup.ts` importa `./i18n` i fa `i18n.changeLanguage('ca')` (idioma fix als tests).

## Inicialització (`i18n/index.ts`)

```ts
import i18n from 'i18next'
import { initReactI18next } from 'react-i18next'
import LanguageDetector from 'i18next-browser-languagedetector'
import ca from './locales/ca/translation.json'
import en from './locales/en/translation.json'

export const SUPPORTED_LNGS = ['ca', 'en'] as const
export type SupportedLng = (typeof SUPPORTED_LNGS)[number]

i18n
  .use(LanguageDetector)
  .use(initReactI18next)
  .init({
    resources: { ca: { translation: ca }, en: { translation: en } },
    fallbackLng: 'ca',
    supportedLngs: SUPPORTED_LNGS,
    interpolation: { escapeValue: false }, // React ja escapa
    detection: {
      order: ['localStorage', 'navigator'],
      caches: ['localStorage'],
      lookupLocalStorage: 'lang',          // clau persistida: "lang"
    },
  })

export default i18n
```

- **Detecció**: primer mira `localStorage['lang']`, després l'idioma del navegador. La selecció de l'usuari es persisteix a `localStorage['lang']`.
- **`escapeValue: false`**: React escapa el contingut, no cal doble escapat.

## Ús als components

```tsx
import { useTranslation } from 'react-i18next'

function MyComponent() {
  const { t, i18n } = useTranslation()
  return (
    <>
      <button>{t('common.save')}</button>
      <span>{t('login.tagline')}</span>
      {/* Interpolació */}
      <p>{t('mainContent.messagePlaceholder', { name: channel.name })}</p>
      {/* Idioma actiu */}
      <small>{i18n.resolvedLanguage}</small>
    </>
  )
}
```

Fora de component (funcions mòdul-scope), es pot importar `i18n` directament:

```ts
import i18n from '../i18n'
const label = i18n.t('appLayout.tabServer')
```

> Nota: `i18n.t` fora d'un component **no** provoca re-render en canviar d'idioma. Fes-ho servir només si el component pare ja es re-renderitza (p.ex. dins una funció auxiliar cridada al render).

### Selector d'idioma

`components/shared/LanguageSwitcher.tsx` — `<select>` que crida `i18n.changeLanguage(lng)`. Muntat a: `LoginScreen`, `DeviceUnlockScreen` i el menú d'usuari (`sidebar/ChannelList`).

## Convenció de claus

- **Namespace de primer nivell per pantalla/modal/panell**: `login`, `unlock`, `channels`, `admin`, `messageList`…
- **`common`** per a text compartit entre múltiples vistes: `common.save`, `common.cancel`, `common.creating`, `common.erase`…
- **`apiErrors`** per als codis d'error del backend (clau = codi numèric, p.ex. `apiErrors.1002`).
- Claus en `camelCase`, descriptives: `errNameRequired`, `confirmDelete`, `tabServer`.
- **Reutilitza** claus existents abans de crear-ne de noves (p.ex. `login.username` per a tots els camps "Nom d'usuari").

### Interpolació

```json
{ "userCreated": "Usuari {{username}} creat" }
```

```tsx
t('admin.userCreated', { username: 'agusti' })
// → "Usuari agusti creat"
```

### Text amb `<strong>` enmig

i18next no injecta HTML per defecte. Per a marcatge enmig d'una frase, parteix la clau en pre/post:

```json
{ "lastAdminPre": "Ets l'últim administrador de",
  "lastAdminPost": ". Si surts, el servidor es quedarà sense admins." }
```

```tsx
{t('leaveServer.lastAdminPre')} <strong>{name}</strong>{t('leaveServer.lastAdminPost')}
```

## Errors del backend (`apiError.ts`)

El backend respon `{ error: { code, message, details } }` amb `message` en català (veure [ERRORS.md](ERRORS.md)). El frontend tradueix pel **codi**:

```ts
import { translateApiError } from '../i18n/apiError'

const msg = translateApiError(apiError.error)
// t(`apiErrors.${code}`, { ...details, defaultValue: message })
```

- Si existeix `apiErrors.<code>` al catàleg → es fa servir aquella traducció.
- Si no → **fallback** al `message` (català) que ha enviat el backend.
- `details` s'usa per interpolar valors dinàmics: el codi `4001` aporta `max` i el `4004` aporta `max_mb` (veure exemple d'interpolació més amunt).

## Què NO es tradueix (literals intencionals)

- Codis de rol: `User`, `Admin`.
- Badges curts de UI: `MOS`, `FCS`, `TAB`, `FIX`, `CAM`, `SCREEN`, `FILE`.
- Marca: `ChillGroup`, `ChillGroup v2`.
- Placeholders d'exemple tècnics: `general`, `team_plus`, `https://...`.
- Logs interns (`logger.*`) — no són UI visible.

## Com afegir un nou idioma

Exemple: afegir **espanyol (`es`)**.

### 1. Crear el catàleg

Copia el català (base complet) com a punt de partida i tradueix els valors:

```bash
cp frontend/src/i18n/locales/ca/translation.json \
   frontend/src/i18n/locales/es/translation.json
```

Tradueix **tots** els valors del nou fitxer. Mantén idèntics les **claus** i els marcadors d'interpolació (la sintaxi de dobles claus de `i18next`).

### 2. Registrar-lo a `index.ts`

```ts
import es from './locales/es/translation.json'

export const SUPPORTED_LNGS = ['ca', 'en', 'es'] as const

i18n.init({
  resources: {
    ca: { translation: ca },
    en: { translation: en },
    es: { translation: es },   // ← afegit
  },
  // ...
})
```

`SUPPORTED_LNGS` alimenta automàticament el `LanguageSwitcher`, així que la nova opció apareix sola.

### 3. Afegir el nom de l'idioma al namespace `language`

A **cada** catàleg (`ca`, `en`, `es`), afegeix l'etiqueta del nou idioma sota `language`:

```json
"language": { "label": "Idioma", "ca": "Català", "en": "Anglès", "es": "Espanyol" }
```

(El `LanguageSwitcher` mostra `t('language.<lng>')` per a cada idioma de `SUPPORTED_LNGS`.)

### 4. Verificar

```bash
cd frontend
node -e "require('./src/i18n/locales/es/translation.json')"   # JSON vàlid?
pnpm exec tsc --noEmit                                         # tipus OK?
pnpm exec vite build                                           # build OK?
```

### 5. (Opcional) Idioma per defecte / fallback

`fallbackLng` continua sent `ca`. Si vols un fallback diferent o una cadena de fallbacks:

```ts
fallbackLng: ['es', 'ca']
```

## Com afegir/canviar text existent

1. **Localitza el namespace** correcte (per pantalla) o `common` si és compartit.
2. Afegeix la clau a `ca/translation.json` (base) **i** a tots els altres idiomes (`en`, …).
3. Fes servir `t('namespace.key')` al component (mai un literal).
4. Si el text té valors dinàmics, usa interpolació de variables (sintaxi de dobles claus d'`i18next`) en comptes de concatenar strings.
5. Verifica: `node -e "require('...json')"`, `tsc --noEmit`, i els tests afectats.

> ⚠️ Si afegeixes una clau només al català, els altres idiomes faran **fallback** a català (no peta, però queda sense traduir). Mantén els catàlegs sincronitzats.

## Tests

- `src/test-setup.ts` força `i18n.changeLanguage('ca')` → les asercions de text dels tests són en català i deterministes (sense detecció per navegador).
- Els tests que comproven text visible asserteixen els **valors catalans** (p.ex. `getByText('Cancel·lar')`).
- `src/i18n/apiError.test.ts` cobreix el mapeig codi→traducció, la interpolació de `details` i el fallback al missatge del backend.

Comandes:

```bash
cd frontend
pnpm exec vitest run src/i18n            # tests i18n
pnpm exec vitest run                     # suite completa
```

## Cobertura actual

Tota la UI està extreta a `t()`:

- **Auth**: `LoginScreen`, `DeviceUnlockScreen`.
- **Sidebar**: `sidebar/ChannelList`.
- **Modals** (`components/modals/*`): tots.
- **Panells** (`components/main/*`): `ChannelHeader`, `MessageInput`, `MessageList`, `MainContent`, `VoiceArea`, `MediaFilePlayer`, `ServerConfigPanel`, `ChannelConfigPanel`, `AdminUsersPanel`.
- **Layouts**: `AppLayout`, `MobileLayout`.

Idiomes: `ca` (base/fallback), `en`.

## Pendents coneguts / fora d'abast

- `docs-site/` no està internacionalitzat (de moment, intencional).
- Formats de data/hora usen locales fixos (`'ca-ES'`) en alguns punts (`MessageList`); es podrien lligar a `i18n.language` si cal.
